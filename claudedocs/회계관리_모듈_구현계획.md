## 1. 구현 전략 및 원칙

### 1.1 개발 원칙

#### ✅ DO (반드시 따라야 할 원칙)

**개발 진행 원칙**
- 한 번에 하나의 기능만 구현 (단계별 진행)
- 각 단계마다 반드시 테스트 후 다음 단계 진행
- 백엔드 API 먼저 확인/구현 → 프론트엔드 구현
- 기존 코드 스타일 (직원 관리, 사용자 프로필) 참고

**아키텍처 원칙 (프로젝트 .cursorrules 준수)**
- Controller → Service → Repository 경로 엄수
- Controller는 Repository 직접 호출 금지
- Controller ↔ Service 간 데이터 전달은 DTO만 사용
- Entity는 DB 입출력 전용으로만 사용

**코드 품질 원칙**
- SOLID, DRY, KISS, YAGNI 원칙 준수
- TypeScript 타입 안전성 100% 유지
- 에러 핸들링 완벽하게 구현
- 가드절(early return) 적극 활용

**프론트엔드 원칙**
- 함수형 컴포넌트만 사용 (function 키워드)
- React Query + Axios 패턴 준수
- React Hook Form + Zod 폼 검증
- 에러 메시지는 한국어로 사용자 친화적 작성
- Named Export 사용 권장

**백엔드 원칙**
- 반환 타입: ResponseEntity<ApiResponse>
- 다중 DB 작업 시 @Transactional 필수
- Bean Validation (@NotBlank, @Email, @Size) 적극 활용
- 존재 여부 확인: repository.findById(id).orElseThrow() 패턴

**보안 원칙**
- 하드코딩 절대 금지 (IP, 도메인, 비밀번호, API 키)
- 인증/인가 로직 비활성화 금지 (개발 환경에서도 유지)
- 민감정보는 YML 파일에서 @Value 또는 @ConfigurationProperties로 주입
- 로그에 민감정보 출력 금지

#### ❌ DON'T (피해야 할 사항)

**개발 프로세스**
- 여러 기능을 한 번에 구현하지 않기
- 테스트 없이 다음 단계로 넘어가지 않기
- 기존 작동하는 코드 수정하지 않기

**DB 관리**
- PostgreSQL 외 다른 DB 사용 절대 금지 (MySQL, MariaDB, H2, SQLite 등)
- 사용자가 설정한 DB 정보 임의 수정 금지 (포트, 호스트, DB명, 사용자명, 비밀번호 등)
- DB 연결 오류 시 설정값 변경하지 않고 오류 내용만 공유

**Git 관리**
- 사용자 요청 없이 Git 커밋하지 않기
- Git 워크플로우 순서 변경 금지 (GitLab → GitHub develop → GitHub main)
- 코드 수정 중 자동 커밋 금지

**빌드 및 실행**
- 콘솔에서 mvn 명령어 직접 실행 금지 (IDE Maven 통합 기능만 사용)
- 사용자 확인 없이 백엔드 서버 재기동하지 않기

**코드 스타일**
- Controller에서 Repository 직접 호출 금지
- 클래스 컴포넌트 사용 금지 (함수형만 사용)
- 하드코딩된 설정값 사용 금지
